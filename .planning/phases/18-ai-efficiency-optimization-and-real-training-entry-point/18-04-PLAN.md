<threat_model>
- T-18-11: GPU run silently produces a different model than the CPU run, but promotion_gate accepts it.
  mitigation: GPU runs always compare aggregate PF against a CPU reference run at the same seed; if `abs(pf_delta) > 0.02`, the production pointer is NOT updated and the GPU run is tagged `device=cuda, accepted=false` in run_manifest.json.
- T-18-12: run_manifest.json schema drift breaks downstream tooling that reads version.json.
  mitigation: run_manifest.json is a separate file; version.json schema is unchanged. The manifest is additive.
- T-18-13: Smoke test pollutes ai_engine/saved_models with throwaway versions.
  mitigation: `--smoke` writes to `tempfile.mkdtemp(prefix="goldbot_smoke_")` and the smoke test asserts ai_engine/saved_models has no new version dir after the test finishes.
- T-18-14: Profiling-regression test flakes on shared CI runners (variable CPU).
  mitigation: Test runs locally / nightly only — NOT in CI. It's gated by env var `GSD_RUN_PROFILING_TESTS=1`. CI runs `pytest -m "not profiling"` by default.
</threat_model>

  <action>
    In `ai_engine/models/xgboost_model.py`:
    1. Accept a `device: str = "cpu"` parameter on the model wrapper class constructor (or via training kwargs).
    2. When `device == "cuda"`, pass `tree_method="hist"` and `device="cuda"` to `XGBClassifier` (XGBoost ≥2.x API — replaces deprecated `gpu_hist`).
    3. Wrap the fit in a try/except `xgboost.core.XGBoostError`; on GPU init failure, log a warning `XGBoost GPU init failed: {exc}; falling back to CPU` and re-run with `device="cpu"`.

    In `ai_engine/models/lightgbm_model.py`:
    1. Accept `device: str = "cpu"` analogously.
    2. When `device == "cuda"` (or "gpu" alias), pass `device="gpu"` to LightGBM params.
    3. On GPU init failure (likely on Windows pip-installed wheels — they're CPU-only by default; this is documented in CONTEXT.md), log a warning and fall back to CPU.

    In `start_ai_training.py`:
    1. Add `--device {cpu,cuda}` flag (default "cpu").
    2. Pass through to `scripts/train_models.py` invocations (which already forwards kwargs to the model wrappers).

    Equivalence guard (in pipeline.py):
    - When `device == "cuda"`, run a control walk-forward window on CPU first with the same seed. Compute `pf_cpu`. Then run the full GPU walk-forward. Compute `pf_gpu`.
    - If `abs(pf_gpu - pf_cpu) / pf_cpu > 0.02`: set `run_manifest["device_accepted"] = False`, log error, DO NOT update production.json pointer. The version dir is still written for diagnostics.
    - If equivalent: set `run_manifest["device_accepted"] = True`, proceed normally.
  </action>
