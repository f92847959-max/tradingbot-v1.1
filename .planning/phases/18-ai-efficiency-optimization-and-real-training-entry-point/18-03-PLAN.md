<objective>
Wave 3: measured optimizations. Adds (a) a per-window feature-matrix LRU disk cache, (b) ProcessPoolExecutor-based parallel walk-forward windows, and (c) lazy-imports of shap/lightgbm/matplotlib so live-mode boot stays fast. All optimizations preserve numerical equivalence and the TRAIN-02 leakage rule.

The acceptance check at the end of the wave reads that baseline.

<threat_model>
- T-18-07: Parallel-window execution introduces non-determinism — same seed, different runs produce different best-model selections.
  mitigation: Each worker uses `seed=base_seed + window_index` (deterministic per window); equivalence test asserts identical aggregated `best_model` and aggregated profit factor (±1e-9) between sequential and parallel runs at the same base seed.
- T-18-08: Feature cache returns stale data when feature_config changes (e.g., new indicator added) — silently degrading model quality.
  mitigation: `compute_feature_config_hash` hashes the FeatureEngineer's configuration dict (list of features + their parameters + version constant); any change invalidates the entire cache.
- T-18-09: Cache directory grows unbounded on a server doing nightly retrains.
  mitigation: LRU eviction triggered when total cache size exceeds the configured cap (default 4 GiB); test asserts evict-on-overflow.
- T-18-10: ProcessPoolExecutor on Windows hangs when the worker imports start_ai_training.py (spawn semantics + side effects).
  mitigation: Worker entry point is a top-level pure function `_train_single_window(args_dict)` in walk_forward.py; no module-level side effects in walk_forward.py or pipeline.py beyond what's already there.
</threat_model>

  <action>
    Create `ai_engine/training/feature_cache.py` with:

    ```python
    class FeatureCache:
        def __init__(self, cache_dir: Path, max_bytes: int = 4 * 1024**3): ...
        def get(self, key: str) -> pd.DataFrame | None: ...
        def put(self, key: str, df: pd.DataFrame) -> None: ...  # triggers LRU eviction when total > max_bytes
        def get_or_compute(self, key: str, compute_fn: Callable[[], pd.DataFrame]) -> pd.DataFrame: ...

    def compute_data_hash(df: pd.DataFrame) -> str: ...  # SHA256 of df.to_csv bytes (stable across runs)
    def compute_feature_config_hash(config: dict) -> str: ...  # sorted JSON dump → SHA256
    ```

    Storage: parquet via pyarrow (already a transitive dep via pandas). Falls back to pickle if parquet write fails. Key format: `{data_hash}_{feature_config_hash}_{window_start_iso}_{window_end_iso}.parquet`. Eviction: on `put`, while `total_bytes > max_bytes`, delete the least-recently-accessed file (atime).

    In `ai_engine/features/feature_engineer.py`:
    1. Add an optional `feature_cache: FeatureCache | None = None` constructor argument.
    2. Add a top-level `compute_features_for_window(self, df_window, window_start, window_end) -> pd.DataFrame` method that:
       - If `self.feature_cache is None`, computes features directly (existing path).
       - Else, calls `self.feature_cache.get_or_compute(key, lambda: self._compute_features_raw(df_window))` where `key = f"{compute_data_hash(df_window)}_{compute_feature_config_hash(self.config)}_{window_start.isoformat()}_{window_end.isoformat()}"`.
    3. The FeatureScaler is NOT cached — it's fit fresh per window AFTER `compute_features_for_window` returns (TRAIN-02 rule). Document this in a top-of-file comment.

    Create `tests/test_feature_cache.py`:
    - `test_get_miss_returns_none`
    - `test_put_then_get_roundtrips`
    - `test_lru_eviction_below_cap`: put N small frames, then one large frame that pushes past cap; assert oldest are evicted
    - `test_compute_data_hash_stable`: same DataFrame → same hash, modified DataFrame → different hash
    - `test_compute_feature_config_hash_ignores_dict_order`
    - `test_train_02_compliance`: build a small dataset, run `compute_features_for_window` twice for the same window with the same cache → second call uses cache; then run `feature_scaler.fit` on the cached features and assert the scaler produces the same scaled output as a fresh-compute path
  </action>
